# Spec — 12-bot Maia roster, 800–1800 (M6 pragmatic slice)

**Bottom line:** the roster grows from 6 to 18 bots. Twelve new personas span
six rungs (800/1000/1200/1400/1600/1800, two contrasting styles per rung),
each playing moves from the human-trained Maia net matching its rung, with
the shipped blunder/mistake tiers layered on top as error injection — heavy
at 800/1000 (dragging maia-1100 below its band), zero at 1600/1800. The
existing six bots are untouched. Verification is the pragmatic tier: full
engine-free pytest + an adjacent-rung monotonic ladder probe; the sealed-eval
and ±150-calibration campaign is deferred to a follow-up ticket
([`../tickets/roster-full-rigor-followup.md`](../tickets/roster-full-rigor-followup.md)).

Owner decisions (2026-08-15 interview): keep all 6 existing bots (18 total);
pragmatic rigor now + full-rigor cleanup ticket; Claude invents names; review
by the approved 5-agent panel.

Rung increment: 200 points, even from 800 to 1800 (user-set endpoints).
Injection dials are non-increasing and threatDistance non-decreasing up the
ladder (test-enforced per backend). 800/1000 both ride maia-1100 (the
published floor); their displayed ratings carry an "est." suffix in the UI
(roadmap M5 honesty decision — no sub-1100 net exists to anchor them).

Temperature does double duty on the Maia path (probe-evidence fold): style
contrast within a rung AND, via `policy_sharpness = 120/temp`, strength
ordering across rungs — every 800 temp is hotter (flatter sampling, weaker)
than every 1000 temp, and so on up. The first probe run proved a sharp
low-rung persona inverts adjacent rungs that share a net. The 1600 rung
keeps a whisper of mistakeRate because the maia-1600 vs maia-1800 self-play
strength gap is compressed (they are move-match models, not strength-scaled
engines).

## Design decisions

1. **`maiaBand` field on `Persona`** (None for the six originals). When set:
   moves come from `maia-<band>.pb.gz`; `elo` becomes a display label allowed
   down to 400 (validation splits by backend — SF-backed personas still
   require a real UCI_Elo ≥ 1320); every Stockfish `candidates()` call clamps
   `max(1320, elo)` so the engine never sees an out-of-range value.
2. **Injection ON TOP of Maia** (roadmap Chapter-4 confirmed shape). The
   pure gates (`should_blunder` → `pick_survivor`, else `should_mistake` →
   `pick_mistake`) run per ply for maiaBand personas; only a firing gate
   costs an SF `candidates()` call. Injection is failure-soft: any bot-engine
   problem keeps the Maia move. `pick_mistake`'s degenerate index-0 returns
   also keep the Maia move (substituting SF-best would SHARPEN play).
   Injected plies still report `engine="maia"` — the indicator's "engine
   fallback" state stays reserved for lc0 actually failing.
3. **Style contrast on the Maia path = policy sharpness.** Two same-band
   personas would otherwise be identical. `pick_from_priors` gains a
   `sharpness` exponent (weights `p**sharpness`; eligibility still raw-p vs
   the 2% howler cutoff), mapped from the persona temperature via
   `policy_sharpness` (120/temp clamped to [0.5, 2.5]). Legacy casey path
   passes the default 1.0 — M2 draw-for-draw identical. **Honest caveat
   (refuter fold):** sharpness is a variety-for-strength trade — the hot
   style plays the net's top move materially less often (~43% vs ~71% on a
   representative distribution), so the two styles at a rung are NOT
   equal-strength; both stay inside the net's ≥2%-prior human-move pool,
   and the offset is absorbed by the approximate rating labels. This
   applies at every rung, including 1600/1800 where injection dials are
   zero — "zero injection" means no blunder/mistake tiers, not "argmax
   only".
4. **casey unchanged.** The legacy `MAIA_NETS` map still wins in
   `_net_path_for`; casey keeps M1/M2 semantics (no injection, no sharpness)
   until the M4 ladder switch.
5. **Rail groups by rung.** Cards sort weakest→strongest with a heading per
   elo group; picker sorts the same way. Data-driven — no per-persona
   frontend code. Avatars remain the user's standing task (initials
   fallback until images land in `data/avatars/`).

## Verification (this slice)

  unrelated tests). New tests: maiaBand validation, band→net resolution,
  sharpness math + M2 back-compat, injection wiring + clamp + failure-soft,

  `docs/analytics/`.
- Browser (Playwright): 18-card grouped rail, est. labels, play a new bot.

## Known limitations (accepted)

- **SF fallback for zero-dial personas is stiff.** When a 1600/1800 bot's
  net is missing, the fallback plays weakened-SF best moves post-opening
  with no error dials — deterministic and engine-textured. Accepted as a
  degraded mode; the rail indicator says "Maia: net missing — plays
  Stockfish" so the state is visible.
- **Injected plies report `engine="maia"`.** The field means "which move
  pipeline served this move"; the indicator's fallback state is reserved
  for real lc0 failures (documented on the response model).
- **`tools/realism_audit.py` bands start at 1300** — it cannot yet audit
  the 800–1200 rungs (extension is in the follow-up ticket).
